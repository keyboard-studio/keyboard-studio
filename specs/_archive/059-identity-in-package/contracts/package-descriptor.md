# Contract: the package-descriptor writer

**Module**: `packages/engine/src/package-descriptor/` · exported from `packages/engine/src/index.ts`

The single writer of the package descriptor's identity fields (FR-005). Both authoring tracks and
the projection reach the `.kps` only through this module. A second writer is a defect.

---

## 1. Interface

```ts
/** Identity the descriptor declares. See data-model.md §1 for fallbacks. */
export interface PackageDescriptorIdentity {
  displayName: string;
  languageTag?: string;
  languageName?: string;
}

/**
 * Build a complete, buildable `.kps` from scratch.
 * Moved verbatim from the scaffolder's private `buildKpsContent`, with the
 * `languages: string[]` parameter replaced by `identity`.
 */
export function buildKpsContent(
  keyboardId: string,
  identity: PackageDescriptorIdentity,
  kmnText: string,
  version?: string,        // default "1.0"
): string;

/**
 * Write the author's identity into `source/<keyboardId>.kps`, GENERATING the
 * file through `buildKpsContent` when it is absent (the adapt track — FR-006,
 * research D-09).
 *
 * Mutates `vfs` in place. Never throws for an absent or unparseable descriptor:
 * it reports through `warnings` so the caller can surface the failure. Silent
 * absence is not an acceptable outcome (FR-006, contrast E-6).
 */
export function applyIdentityToKps(
  vfs: VirtualFS,
  keyboardId: string,
  identity: PackageDescriptorIdentity,
  kmnText: string,
  version?: string,
): { warnings: string[]; generated: boolean };

/**
 * The overlay fields this writer actually consumes. The FR-016 repository check
 * validates every declared `OutputWrite.field` against this set, so a question
 * cannot declare a field no writer reads.
 */
export const DESCRIPTOR_CONSUMED_FIELDS: ReadonlySet<string>;
  // = { "displayName", "bcp47", "languageName" }
```

---

## 2. Elements written

Exactly these, and no others. Element names are the Keyman package format's — copy them verbatim.

| Element | Source | Requirement |
|---|---|---|
| `<Info><Name URL="">` | `displayName` | FR-003 |
| `<Info><Description URL="">` | `displayName` (existing "<name> keyboard, generated by Keyboard Studio." form) | FR-003 |
| `<Keyboards><Keyboard><Name>` | `displayName` | FR-003 |
| `<Keyboards><Keyboard><Languages><Language ID="{tag}">{name}</Language>` | `languageTag` / `languageName` | FR-001, FR-002 |

**Not written by this feature**: `<Keyboards><Keyboard><Version>` (already owned by the adapt
path's existing patch and by `<FollowKeyboardVersion/>`), `<Files>`, `<System>`, `<Options>`.
`welcome.htm` / `readme.htm` **content** is out of scope — the `<Files>` entries naming them are
untouched.

**Language block replacement is total.** The `<Languages>` block is replaced, not appended to. A
descriptor that previously declared the base's `fr` must not end up declaring both `fr` and the
author's tag — SC-002 requires zero delivered packages declaring the base's language.

---

## 3. Escaping

All interpolated values pass through the existing `escapeHtml` before emission, as
`buildKpsContent` already does. A display name containing `&` or `<` must not produce malformed
XML.

---

## 4. Composition with the id-rename pass

`applyIdentityToKps` runs at projection step 3.6, before the step-4 rename, and writes under the
**pre-rename** keyboard id. It must not attempt to rewrite `<ID>` or the `<Files>` paths — step 4's
`rewriteKpsFilePaths` owns that, and its deliberate skip of non-path-shaped `<Name>` values
(`if (!value.includes("/") && !value.includes(".")) return m`) is what preserves the display names
this writer just set. The order is fixed and must not be inverted (research D-02).

---

## 5. Warning strings

House convention: no emoji, bracketed prefix. Engine-side warnings are operator-facing diagnostics,
not author-facing prose, so they are not catalog strings (053 FR-016 governs author-facing text
only — the studio localizes what the author reads).

```
[package-descriptor] generated a package descriptor for <id> (none was present)
[package-descriptor] could not write identity into <path>: <reason>
```

## 6. Callers

| Caller | Entry point | Notes |
|---|---|---|
| `generateStubs` (`packages/engine/src/scaffolder/index.ts`) | `buildKpsContent` | Unchanged behaviour: still only writes when the path is absent. |
| `projectWorkingCopyVfs` step 3.6 (`packages/studio/src/lib/projectWorkingCopyVfs.ts`) | `applyIdentityToKps` | Both tracks. Warnings merge into the projection's `warnings[]`. |

No other caller. In particular `serializeWorkingCopy` must **not** grow a descriptor write of its
own — its existing `<Version>` regex patch stays where it is, and FR-004/SC-005 require the OSK
preview to see the same descriptor the zip does.
