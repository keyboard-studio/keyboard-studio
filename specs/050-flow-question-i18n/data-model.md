# Data Model: Flow-Question Content i18n

This feature adds one entity to the existing Tier B content-i18n model (spec 046's `data-model.md` equivalent lives implicitly in `contentI18n.ts` + the extractor — there is no separate data-model doc for spec 046 since it's a cross-cutting loader, not a new record type). No existing type is renamed or restructured.

## FlowQuestionText (new)

Represents the translatable copy of a single modular flow-engine question.

| Field | Type | Source | Notes |
|---|---|---|---|
| `questionId` | `string` | `FlowQuestion.id` (`packages/studio/src/survey/types.ts:58`) | Unique across all live registries (enforced by `registry.test.ts`'s no-duplicate-id check); the catalog key's `<id>` segment. |
| `prompt` | `string?` | `FlowQuestion.prompt` | Extracted only when defined. |
| `label` | `string?` | `FlowQuestion.label` | Extracted only when defined; some questions use `label` instead of `prompt` (`QuestionField.tsx:764`'s `??` fallback chain). |
| `body` | `string?` | `FlowQuestion.body` | Notice-type questions only (`QuestionField.tsx:730`). |
| `help_text` | `string?` | `FlowQuestion.help_text` | Extracted only when defined. |
| `options` | `{ value: string; label: string }[]?` | `FlowQuestion.options` (`FlowOption`, `types.ts:34-38`) | Each option's `label` is extracted; `value` (the answer-storage key) and `note` are excluded — `value` is control data, `note` has no confirmed render site (mirrors D8's "no confirmed render site" exclusion rule already applied to `criteria.section`). |

**Not extracted** (control fields, never rendered as prose): `id`, `type`, `required`, `options_source`, `next`, `engine_resolved`, `advisory`, `options[].value`, `options[].note`.

**Validation rule**: an empty-string value for any extracted field is dropped from the catalog (mirrors `extractAdaptationQuestionStrings`'s `provenanceLabel.trim().length === 0` skip, `extract.ts:122`) — nothing for a translator to act on.

**Relationships**: One `FlowQuestionText` per `FlowQuestion` node in the live phase registries (`phaseARegistry`/`phaseBRegistry`/`phaseFRegistry`/`phaseGRegistry`); `registry.reserve.ts`'s demoted modules are explicitly excluded (see research.md D2). No relationship to `Pattern`/`Criterion`/`AdaptationQuestion` — a fully independent fourth catalog namespace.

**State / lifecycle**: Purely derived data — regenerated by `pnpm run i18n-content-extract`-equivalent tooling (the same invocation that produces the other three catalogs) whenever a question module's text changes. No runtime mutation; `content-i18n-lint` fails CI if the committed `content/i18n/en/flowQuestions.json` drifts from a fresh extraction.

## Catalog key shape (flat JSON, `content/i18n/{locale}/flowQuestions.json`)

```text
content.flowQuestion.<questionId>.prompt
content.flowQuestion.<questionId>.label
content.flowQuestion.<questionId>.body
content.flowQuestion.<questionId>.help_text
content.flowQuestion.<questionId>.option.<optionValue>.label
```

See [contracts/flow-question-catalog-format.md](contracts/flow-question-catalog-format.md) for the full contract (this is an extension of spec 046's existing Tier B key grammar, not a new grammar).
