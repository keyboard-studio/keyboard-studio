# Spec 104 Touch key identity criteria: as built

**Status:** Implemented 2026-10-17/18 in four waves — PR #2266 (Wave 1: fixtures, tap harness, resolver, decision function, spine records, diagnostics/coverage migration), PR #2267 (Wave 2: rule-join `any()` fix, carve, severance + re-link, derivation surfaces), PR #2272 (Wave 3: guard station, Copy parity gate, repair list, Track 2 choices, key-inspector section, refusal probe), and the Wave 4 branches `km/104-w4-gates` (T021 corpus gate, T022 caps probe) + `km/104-w4-close` (T023 e2e walks, this file, spec-trace registration), integrated on `km/104-w4-implementation`.
**Full docs:** this directory (spec, plan, research, data-model, quickstart, contracts/key-id-criteria.md, tasks). Not read by default.
**Pinned here:** none
**Predecessors:** extends spec 063's key-id policy (`T_<HEX>` does not self-output; `U_` is the no-rule form) and spec 065's inherit-first proposer, superseding both where this spec names a difference (notably FR-013, the combining-mark mint).

## What shipped

- **One production resolver** (FR-003): `resolveTouchProduction()` in contracts answers "what does this key occurrence produce, in this state, from which source" for every consumer — coverage, diagnostics, enumeration, carve, placement replay, combo propagation, the scaffolder, the proposer's inherit gate, and the inspector panel. No consumer keeps a second production model.
- **The criteria as a decision function**: `decideKeyIdForm()` implements the contracts §2 table (arms 0/a/b/c/c′/d/d′/d″/e) as a pure function; the proposer's minting routes through it (FR-005, FR-010).
- **Carve treats T_/U_ as first-class producers** (US4): removal matching and enumeration read production from the resolver; `carveTouchCharacter` neutralises every producing occurrence and suppresses its binding rules in the same operation, with shared bindings suppressed / preserved / separated / refused-with-binding per contracts §4. A ruled U_ carve removes key and rules together (the fail-open trap, FR-020).
- **Severance and re-link** (FR-008, FR-029): `severTouchKey()` transplants a K_-linked key's binding rules verbatim onto the minted id (rule nodes incl. `if()` guards, group and relative order preserved), scoped to the layer family where arm 0 failed; refusals (shared binding, group/order, target collision, opaque fragments) emit zero clones and name the binding. `relinkTouchKey()` is its mirror.
- **Creation integration** (US1): a redefining edit on a K_-linked key severs automatically on creation/Copy; a label-only edit never does (FR-011, FR-012). The severance line ships as en/fr descriptors (FR-026).
- **The guard specification** (FR-013): asked once per keyboard at the marks step's guard station (seeded from the imported keyboard on Track 2, presented for confirmation; provisional until confirmed), recorded as a decision-registry entry, and threaded into every studio minting caller — marks mint guarded T_ only under a recorded "swallow" specification, else U_.
- **Copy** (US2): a tap-simulation parity gate in the copy flow (T014) and the repair list at the touch step — dead T_ keys with the criteria default preselected (guard-aware per FR-009), answers recorded as `RepairProposal` outcomes; unvisited repairs pass through unapplied at download and are listed at Output (FR-015 as clarified).
- **Adapt** (US3): identity changes are the author's choice — import/carve-triggered sets through the repair-list pattern, editor-triggered severance decided inline in the key property panel at commit; on transplant refusal the choice collapses to keep-the-link vs flag-for-manual-definition with the binding shown (FR-016). A decline leaves identity + rules byte-identical, is recorded, and suppresses re-presentation until the underlying state changes (FR-017).
- **Derivation surfaces** (US5): placement replay addresses the resolver-proven occupant of a slot; combo propagation preserves divergent T_/U_ slots and includes the bare combo; the scaffolder places ruled T_/U_ vkeys under their original ids (FR-021, FR-022).
- **Inspectability** (US6): the key property panel shows the key's FR-005 criterion, a production table covering only the states the key occurs in (conditional productions per condition, sources named, fallback-supplied states marked) in a disclosure closed by default, and the key's identity-decision provenance — all computed from the resolver + spine records (FR-025). The FR-029 re-link action is offered from the panel wherever arm 0 holds again.
- **Corpus gate + caps verdict** (Wave 4): the resolver⇔consumer equivalence gate sweeps the corpus as an engine test (T021, FR-027 — see "Wave 4 gates" below), and the caps-state K_ fallback question left open by the research is settled by tap probe: the fallback fires in caps state (T022).
- **Evidence** (T026): the refusal-rate corpus probe (`utilities/refusal-probe/`) ran the transplant over every corpus keyboard's K_-linked touch keys: **745 keys probed, candidate refusal rate 12.4%** of genuine severance candidates (raw rate 17.7% of all requests, including arm-0-holds cases that never needed severance; per-keyboard rates and binding causes in `utilities/refusal-probe/refusal-report.md`). These numbers sized the Track 2 choice UX before it was built.

## Decisions and adjudications recorded during the build

- **Resolver in contracts, not engine.** The plan put the production resolver where every consumer can import it: keyboard-lint cannot import engine, so the resolver and the decision function live in `packages/contracts` (spec's Ownership section). The Wave 1 dependency cycle this created (touchProduction ↔ touch-coverage) was fixed by extracting leaf utilities into `touch-key-ids.ts`, not by moving the resolver.
- **Rule-join `any()` expansion.** The spec assumed the spec 063 join exposed fan-rule bindings; it did not (a fan rule `+ any(fanHkeys) > index(fanH,1)` has no vkey element). The join now expands key-position `any(store)` into per-key bindings with index-aligned produced characters; context-position `any()` never expands, and an unalignable `index()` contributes no invented output. Without this, carve of a fan character silently no-oped.
- **Derive readings on occupancy (T017).** Placement replay's occupant is the production-proven key at a slot, not the positional one: a rule-free T_ key at a slot is NOT an occupant (the miss is reported and the fallback append applies), and occupancy is never inferred from position alone. Ruled U_ vkeys receive the scaffolder's ruled-T_ treatment (T019).
- **The `trySeparate` seam fix.** Carve's separation step requests only the OUTPUT-store slot; spec 076's slot machinery drops the parallel key-store position by coordination. Requesting the vkey-store slot directly is refused by that machinery's char check and silently dropped the whole separation — found when the fv_ fan test was restored in Wave 2 integration.
- **Guard-spec source unification.** The guard specification has one source of truth: the marks-treatment decision record. Studio minting callers read it through `effectiveGuardSpecification` (TouchGallery / AssignPanel / RenameDialog / keyGrid commands); a second, working-copy-carried copy of the field exists in the store's types but is NOT read by any minting path (leftover — see Follow-ups).
- **FR-017 as fingerprint-pinned suppression.** A declined inline choice pins (key address, source id, target id, fingerprint of the source key's IR bindings). An identical later edit commits under the standing answer without re-presentation; a changed fingerprint, a different target, or a newer decision for the key re-opens the question. The repair-list half of FR-017 is the visible-and-answered row (declined rows stay, with a Change answer affordance).
- **One call site deliberately unthreaded.** `useKeyCommands`' blank-key creation path does not consult the guard specification: a blank key has no production and no mark, so there is nothing for the specification to decide. Recorded here so the omission reads as a decision, not an oversight. (The other six previously-orphaned surfaces — AssignPanel, RenameDialog, RemoveKeyDialog, FamilyApplyDialog, FindPanel, mode-context carry — ARE threaded.)
- **`applyTouchAssignments`' `touch_key_replace` is not severance-wired.** Assign-path ids are governed by the proposer (T010), which routes through `decideKeyIdForm`; wiring the replace op into the transplant as well would double-govern the same ids.

## Gotchas and limits

- **The marks series now ends at a question.** Since Wave 3, the guard station is always the marks series' last station and its Continue is disabled until answered (seed/prior/author pick). The shared e2e driver `driveMarksSeries` answers an unanswered station with "swallow" — the pre-104 guarded default the legacy walks were written against — and never overrides a seed or prior (`answerGuardStationIfPresent` in `e2e/helpers/surveyFlow.ts`).
- **`touch-key-assign.spec.ts` (spec 063 SC-004) predates the FR-018 hold.** Its walk takes the survey's Adapt radio — which lands in `instantiateFromExisting` (adapt-existing) — and asserts the assign commit lands directly on Enter. On the adapt track the commit is now HELD for the identity choice, so that spec's post-Enter assertions need a choice answer added before they can pass again. It is not in the CI e2e lane's filter list (boot-smoke, copy-edit, decision-store-reload, + spec 104's walks), so this is a local-run follow-up, not a lane failure.
- **The store comment on `instantiateFromExisting` is stale.** workingCopyStore.ts says Track 2's UI entry point "does not yet exist"; StudioShell's choose_base commit routes the authoring-track adapt answer to it. The comment predates that wiring.
- **Caps-state K_ fallback fires (T022, settled).** An unmatched K_ key on a caps layer produces the state-0 character (caps+SHIFT: the shifted character); the resolver returns the ordinary k-fallback record with `fallbackCertain: true` — the contracts §5 proviso is gone. Witness-proven by the `caps_probe` fixture's `[CAPS K_B]`/`[NCAPS K_B]` pair (see T022 below).

## Wave 4 gates (completed at integration)

- **T021 — corpus gate (FR-027): landed as an engine corpus-sweep test**, `packages/engine/src/pattern-apply/touchProductionEquivalence.corpus.test.ts` — a location delta from the task's `tools/` home, justified on the record: the repo's utilities probes are explicitly non-gates (the T026 precedent), and the corpus-test pattern is the only route into the nightly soak (the path-gated corpus step in ci.yml, hence the dev soak) without a ci.yml change. For every corpus keyboard with a touch layout the gate checks: (1) dead-key scan ⇔ resolver agreement (zero tolerance), (2) coverage loses no resolver production, (3) removal enumeration ⇔ resolver address agreement (zero tolerance; also pins the "vice versa" flip direction), (4) the flip population — resolver-dead T_ ids carrying keycap text, i.e. the FR-009 repair population — enumerated per keyboard. Tolerated divergences are predicate-classified delta classes only, pinned exactly for verified keyboards: COV-UNREACHABLE-LAYER (productions confined to layers no nextlayer chain reaches from "default" — the one instance is akan, 47 units, no nextlayer keys in its layout) and FLIP-DEAD-TEXT (the flip population itself). FR-027's copy/adapt production-diff arm is discharged by T014's copy-parity gate plus this gate's resolver agreement; refusal rates are T026's report. Local run over the partial checkout (13 of 962 keyboards): **14/14 pass**, zero-tolerance arms clean, flip population = the 5 `basic_*` templates × {T_002C, T_002E, T_003A, T_FCFA}; a negative control (doctored pins) fails as designed. The full-corpus first run is pending the nightly soak. Enabler landed alongside: the resolver memoises its per-IR lookup maps (WeakMap keyed on the IR object, so a replaced IR gets fresh maps — staleness-pinned by test) per plan.md's Performance Goals; without it the enumeration arm cost ~55 s on sil_cameroon_azerty alone (≈310 s total), with it the whole local sweep runs in ~31 s (≈14 s under vitest).
- **T022 — caps-fallback probe: SETTLED — the fallback FIRES in caps state.** Witness-guarded tap probe over the hand-constructed `caps_probe` fixture (its `[CAPS K_B]`/`[NCAPS K_B]` witness pair mirrors sil_cameroon_azerty's corpus usage): an unmatched K_Q on a caps layer types `q` (the state-0 character), on caps+SHIFT types `Q`; the witness pair proves CAPITAL genuinely engaged (the caps rule fires only on the caps layer), and a state-free rule also fires under CAPITAL (secondary observation, pinning the resolver's not-Lstate-gated binding treatment). Mechanism: KMW's `forBaseKeys` gates on `Lmodifiers` alone. The resolver drops the caps unknown arm — a caps-state K_ returns the ordinary k-fallback record with `fallbackCertain: true` — and the contracts §5 proviso is removed (rewritten as the settled verdict); the spec edge case, research.md §1, and data-model.md are updated to match.
