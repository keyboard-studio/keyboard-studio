# Security and privacy reporting

## Security vulnerabilities

Report vulnerabilities **privately**: use GitHub's private
vulnerability reporting on this repository — the **Security** tab →
**Report a vulnerability**. Only the maintainers and you can see a
private report.

Please do **not** open a public issue for a vulnerability — a public
issue discloses the problem to everyone before it can be fixed.

## Privacy and data requests

The same private route serves **privacy requests** — access to your
data, erasure, or any question about how Keyboard Studio handles
personal data. Open a private report via **Security → Report a
vulnerability** and title it as a privacy request (for example,
"Privacy request: export my server drafts"). It reaches the privacy
owner privately, and the one-month response clock runs from the day
it arrives.

What we hold and how requests work is described in the privacy notice
(in the app, and in `docs/privacy/` in this repository: the processing
record, and the access and erasure procedures).
